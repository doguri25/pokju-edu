## 1. 한 줄 요약

폭주전설의 3D 주행 엔진 위에서, 화면에 문제가 뜨면 **정답이 적힌 깃발 문을 지나가거나 정답 물체를 맞혀서** 푸는 초등 학습 게임. 첫 과목은 **구구단**, 다음은 **맞춤법**.

## 2. 왜 만드는가

- 구구단은 외우는 연습을 많이 해야 하는데, 문제지 반복은 아이들이 금방 지루해한다.
- 달리는 게임은 "몇 초 안에 고르기"가 자연스럽게 들어 있어 **빠르게 떠올리는 연습(유창성)** 에 잘 맞는다.
- 폭주전설에는 이미 도로, 차량 52종, 배경 8곳, 날씨, 터치·키보드·게임패드 조작, 효과음, 기기 저장이 있어서 새로 만들 것이 적다.

조심할 점

## 5. 핵심 놀이 방식

### 5.1 한 문제의 흐름 (깃발 모드, 기본)

1. 화면 위쪽 문제 칩에 문제가 뜬다. 예: **7 × 8 = ?**
2. 멀리서 깃발 문 두 개가 다가온다. 왼쪽 문에 **54**, 오른쪽 문에 **56**.
3. 학생은 차를 왼쪽이나 오른쪽으로 옮겨 한쪽 문을 지나간다.
4. 맞으면: 반짝임, 효과음, 짧은 가속(니트로), 별(점수) +1, 연속 정답 콤보.
5. 틀리면: 차가 잠깐 느려지고, 문제 칩에 **7 × 8 = 56** 이 정답으로 2초 동안 크게 보인다. 그 문제는 같은 판 뒤쪽에 한 번 더 나온다.
6. 문을 하나도 안 지나면(가운데로 빠짐) "놓침"으로 치고 정답을 보여 준다.

### 5.2 생각할 시간 보장

- 문제가 뜬 뒤 문에 닿기까지의 시간은 **속도가 아니라 시간으로 정한다**. 난이도 「천천히」 6초, 「보통」 4초, 「빠르게」 2.5초. 차 속도에 맞춰 문이 나타나는 거리를 계산한다.
- 문제가 떠 있는 동안 다른 장애물(적, 일반 차)은 나오지 않는다. 문제 사이 쉬는 구간에만 가벼운 장애물을 둔다.

### 5.3 맞히기 모드 (두 번째 단계)

- 길 위에 답이 적힌 풍선(또는 상자) 2~4개가 떠서 다가온다.
- 정답 풍선을 쏘아 맞히면 정답. 오답 풍선을 맞히거나 정답 풍선을 그냥 지나치면 틀림.
- 원본 보급 상자의 "쏘면 반응" 판정을 재사용한다.

### 5.4 한 판 구성

- 한 판 = 문제 10개 (설정에서 5 / 10 / 20).
- 끝나면 결과 화면: 맞힌 수, 평균 답한 시간, 가장 오래 걸린 문제, 틀린 문제 다시 보기.
- 별을 모아 차량을 연다 (원본의 고철·차량 해금 구조를 그대로 씀).

## 6. 구구단 콘텐츠 설계

### 6.1 문제 유형 (단계별로 열림)

| 단계 | 유형 | 예 |
| --- | --- | --- |
| 1 | 단 하나, 순서대로 | 2×1, 2×2, 2×3 … |
| 2 | 단 하나, 섞어서 | 2×7, 2×3, 2×9 … |
| 3 | 여러 단 섞기 | 3×6, 7×4, 5×8 … |
| 4 | 빈칸 찾기 | 6 × □ = 42 |
| 5 | 거꾸로 (나눗셈 준비) | 56 = 7 × □ |

### 6.2 오답(헷갈리는 답) 만드는 규칙

아무 숫자가 아니라 **아이들이 실제로 잘 틀리는 답**을 보기로 낸다.
- 이웃 곱: a×(b±1), (a±1)×b → 7×8의 보기로 49, 63, 48, 64
- 끝자리 같은 수: 56 → 36, 46
- 곱셈 대신 덧셈: 7+8 = 15
- 0과 1 함정: 6×1 → 7, 6×0 → 6
- 보기에 같은 숫자가 두 번 나오지 않게 하고, 정답이 왼쪽·오른쪽에 반반 오도록 섞는다.

### 6.3 반복 학습

- 문제(예: 7×8)마다 맞힌 횟수, 틀린 횟수, 답한 시간을 저장한다.
- 다음 판을 만들 때 틀렸거나 오래 걸린 문제를 더 자주 낸다 (약한 문제 40%, 새 문제 40%, 잘 아는 문제 20%).
- 결과 화면과 기록 탭에 **9×9 표** 로 "잘함 / 연습 중 / 어려움"을 색과 기호로 보여 준다 (색만으로 구분하지 않음).

## 7. 맞춤법 확장 (2단계 과목)

- 같은 깃발 두 개 구조를 그대로 쓴다. 예: 문제 "숙제를 다 ___" → 왼쪽 **했어**, 오른쪽 **했써**
- 처음 묶음 후보: 되/돼, 안/않, 로서/로써, 맞히다/맞추다, 바라다/바래다, 웬/왠, -든지/-던지, 받침 헷갈림(낫다/낮다/났다), 띄어쓰기 기초.
- 문제는 코드와 따로 **문제 묶음 파일(JSON)** 로 둔다. 교사가 문제를 추가할 수 있게 하는 것이 목표.

```json
{ "subject": "spell", "set": "되-돼", "items": [
  { "q": "이제 집에 가도 ___?", "a": "돼", "wrong": ["되"], "why": "'되어'로 바꿔 말이 되면 '돼'" }
] }
```

## 10. 기술 방향

- 원본과 같은 방식: `src/` 조각 + `build.sh` → `index.html` 한 파일, Three.js r128, GitHub Pages.
- 새 조각 파일: `js_quiz.js`(출제기·오답 생성·반복 학습), `js_gate.js`(깃발 문·판정), `js_learn_ui.js`(고르기·결과·기록 화면), `data/*.json`(문제 묶음, 빌드 때 합침).
- 출제기는 3D와 분리된 순수 함수로 만들어 Node로 단위 시험한다 (오답 규칙, 정답 위치 반반, 중복 없음).
- 저장: `localStorage` 새 키 `pokju-edu-v1`. 이름·학번 같은 개인정보는 저장하지 않는다.
- **결정: 서버 없음.** 기록은 각 기기에만 저장하고, 교사는 결과 화면을 눈으로 확인한다. 반 기록 모으기는 필요해지면 따로 설계한다.

## 11. 성공 기준

- 학생 한 판(문제 10개)이 3분 안에 끝난다.
- 같은 학생이 5판 뒤 구구단 정답률과 평균 답한 시간이 좋아진다 (기록 탭에서 확인 가능).
- 보급형 태블릿에서 화질 「낮음」으로 30fps 이상.
- 출제기 단위 시험 통과: 81개 곱셈 모두 보기 중복 없음, 정답 위치 왼쪽·오른쪽 비율 45~55%.
