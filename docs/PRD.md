## 1. 한 줄 요약

폭주전설의 3D 주행 엔진 위에서, 화면에 문제가 뜨면 **정답이 적힌 깃발 문을 지나가거나 정답 물체를 맞혀서** 푸는 초등 학습 게임. 첫 과목은 **구구단**, 다음은 **맞춤법**.

## 2. 왜 만드는가

- 구구단은 외우는 연습을 많이 해야 하는데, 문제지 반복은 아이들이 금방 지루해한다.
- 달리는 게임은 "몇 초 안에 고르기"가 자연스럽게 들어 있어 **빠르게 떠올리는 연습(유창성)** 에 잘 맞는다.
- 폭주전설에는 이미 도로, 차량 52종, 배경 8곳, 날씨, 터치·키보드·게임패드 조작, 효과음, 기기 저장이 있어서 새로 만들 것이 적다.

## 3. 가능성 검토 (원본 코드를 보고 확인한 것)

**결론: 가능하다.** 새로 짜야 하는 것은 "문제 출제기", "깃발 문", "학습 기록과 결과 화면" 세 가지가 중심이고, 나머지는 원본을 줄이거나 바꾸는 일이다.

조심할 점
- 원본은 약 2만 행이 하나의 함수 안에 묶여 있어서, 쓰지 않는 기능(미션 38개, 보스, 폭격 등)을 빼는 작업이 생각보다 손이 간다. 처음에는 **끄기만 하고**, 안정되면 지운다.
- 학교 크롬북·보급형 태블릿은 3D가 무거울 수 있다. 화질 「낮음」을 기본값으로 시작하는 방안을 검토한다.
- 전투·폭발 표현은 빼기로 했다. 무기·적 코드가 다른 부분과 얽혀 있어 하나씩 끄면서 확인해야 한다.

## 4. 대상 사용자

**결정: 교실 수업용이 중심이다.** 교사가 단과 난이도를 정해 주고 학생이 10분 안팎으로 푼다. 집에서 쓰는 것은 막지 않지만 우선순위는 낮다.

| 사용자 | 바라는 것 |
| --- | --- |
| 학생 (초등 2~4학년) | 재미있게, 틀려도 부끄럽지 않게, 짧게 한 판 |
| 교사 (주 사용자) | 수업 10분 활동으로 쓰기, 단을 골라 주기, 학생 화면의 결과를 보고 어려워하는 단 파악하기 |
| 보호자 | 집에서 연습, 결과 확인 |

구구단은 초등 2학년 2학기 교육과정이다. 3~4학년은 복습·속도 연습용으로 쓴다.

## 5. 핵심 놀이 방식

### 5.1 한 문제의 흐름 (깃발 모드, 기본)

1. 화면 위쪽 문제 칩에 문제가 뜬다. 예: **7 × 8 = ?**
2. 멀리서 깃발 문 두 개가 다가온다. 왼쪽 문에 **54**, 오른쪽 문에 **56**. (높은 단계에서는 문이 3~4개, 6.4 참고)
3. 학생은 차를 왼쪽이나 오른쪽으로 옮겨 한쪽 문을 지나간다.
4. 맞으면: 반짝임, 효과음, 짧은 가속(니트로), 별(점수) +1, 연속 정답 콤보.
5. 틀리면: 차가 잠깐(약 1.5초) 느려지고, 문제 칩에 **7 × 8 = 56** 이 정답으로 2초 동안 크게 보인다. 그 문제는 같은 판 뒤쪽에 한 번 더 나온다.
6. 문을 하나도 안 지나면(가운데로 빠짐) "놓침"으로 치고 정답을 보여 준다.
7. 벌칙은 느려지기까지만이다. 내구가 깎이거나 판이 끝나는 일은 없다. 틀린 문제를 끝까지 풀 수 있어야 연습이 되기 때문이다.

### 5.2 생각할 시간 보장

- 문제가 뜬 뒤 문에 닿기까지의 시간은 **속도가 아니라 시간으로 정한다**. 난이도 「천천히」 6초, 「보통」 4초, 「빠르게」 2.5초. 차 속도에 맞춰 문이 나타나는 거리를 계산한다.
- 문제가 떠 있는 동안 다른 장애물(적, 일반 차)은 나오지 않는다. 문제 사이 쉬는 구간에만 가벼운 장애물을 둔다.

### 5.3 맞히기 모드 (두 번째 단계)

- 길 위에 답이 적힌 풍선(또는 상자) 2~4개가 떠서 다가온다.
- 정답 풍선을 쏘아 맞히면 정답. 오답 풍선을 맞히거나 정답 풍선을 그냥 지나치면 틀림.
- 원본 보급 상자의 "쏘면 반응" 판정을 재사용한다.

### 5.4 한 판 구성

- 한 판 = 문제 10개 (설정에서 5 / 10 / 20).
- 끝나면 결과 화면: 맞힌 수, 평균 답한 시간, 가장 오래 걸린 문제, 틀린 문제 다시 보기.
- 별을 모아 차량을 연다 (원본의 고철·차량 해금 구조를 그대로 씀).

## 6. 구구단 콘텐츠 설계

### 6.1 문제 유형 (단계별로 열림)

| 단계 | 유형 | 예 |
| --- | --- | --- |
| 1 | 단 하나, 순서대로 | 2×1, 2×2, 2×3 … |
| 2 | 단 하나, 섞어서 | 2×7, 2×3, 2×9 … |
| 3 | 여러 단 섞기 | 3×6, 7×4, 5×8 … |
| 4 | 빈칸 찾기 | 6 × □ = 42 |
| 5 | 거꾸로 (나눗셈 준비) | 56 = 7 × □ |

### 6.2 오답(헷갈리는 답) 만드는 규칙

아무 숫자가 아니라 **아이들이 실제로 잘 틀리는 답**을 보기로 낸다.
- 이웃 곱: a×(b±1), (a±1)×b → 7×8의 보기로 49, 63, 48, 64
- 끝자리 같은 수: 56 → 36, 46
- 곱셈 대신 덧셈: 7+8 = 15
- 0과 1 함정: 6×1 → 7, 6×0 → 6
- 보기에 같은 숫자가 두 번 나오지 않게 하고, 정답이 왼쪽·오른쪽에 반반 오도록 섞는다.

### 6.3 반복 학습

- 문제(예: 7×8)마다 맞힌 횟수, 틀린 횟수, 답한 시간을 저장한다.
- 다음 판을 만들 때 틀렸거나 오래 걸린 문제를 더 자주 낸다 (약한 문제 40%, 새 문제 40%, 잘 아는 문제 20%).
- 결과 화면과 기록 탭에 **9×9 표** 로 "잘함 / 연습 중 / 어려움"을 색과 기호로 보여 준다 (색만으로 구분하지 않음).

### 6.4 보기 개수

| 단계 | 보기 | 깃발 문 위치 |
| --- | --- | --- |
| 1~3 | 2개 | 왼쪽 두 차로 한 칸, 오른쪽 두 차로 한 칸 |
| 4 | 3개 | 왼쪽·가운데·오른쪽 |
| 5 | 4개 | 차로 4개에 하나씩 |

보기가 늘어도 생각할 시간(5.2)은 줄이지 않고 0.5초씩 늘린다.

## 7. 맞춤법 확장 (2단계 과목)

- 같은 깃발 두 개 구조를 그대로 쓴다. 예: 문제 "숙제를 다 ___" → 왼쪽 **했어**, 오른쪽 **했써**
- 처음 묶음 후보: 되/돼, 안/않, 로서/로써, 맞히다/맞추다, 바라다/바래다, 웬/왠, -든지/-던지, 받침 헷갈림(낫다/낮다/났다), 띄어쓰기 기초.
- 문제는 코드와 따로 **문제 묶음 파일(JSON)** 로 둔다. 교사가 문제를 추가할 수 있게 하는 것이 목표.

```json
{ "subject": "spell", "set": "되-돼", "items": [
  { "q": "이제 집에 가도 ___?", "a": "돼", "wrong": ["되"], "why": "'되어'로 바꿔 말이 되면 '돼'" }
] }
```

## 8. 이야기

원본처럼 이야기를 따라가며 단을 하나씩 깨는 「이야기 모드」를 기본으로 둔다. 원본의 도시와 인물을 그대로 쓰되, 싸움 대신 **고장 난 AI를 문제를 풀어 고쳐 주는 이야기**로 바꾼다. 교실에서는 이야기를 건너뛰고 단을 바로 고르는 「연습 모드」도 쓴다.

### 8.1 배경과 인물

| 인물 | 원본 | 학습판 |
| --- | --- | --- |
| 나 (플레이어) | 전설 카센터 막내 정비사 | 그대로. 한울시에서 운전대를 잡을 줄 아는 몇 안 되는 사람 |
| 오 사장 | 카센터 사장, 무기를 달아 줌 | 차를 고쳐 주고, 깨운 구역마다 새 차를 내어 줌. 무뚝뚝하지만 칭찬에 후함 |
| 새벽 | 관제사, 무전으로 길 안내 | 무전으로 문제를 읽어 주는 대신 **힌트**를 준다 (예: "7단은 7씩 커져. 7×7이 49였지?") |
| 마성 | 폭주한 관제 AI, 적 | **나쁜 AI가 아니라 계산 칩이 고장 난 AI.** 숫자를 까먹어 신호등, 버스 시간, 택배 개수가 다 엉망이 됐다. 마지막에 고쳐져 친구가 된다 |

### 8.2 줄거리

- **프롤로그 (장면 3장):** 한울시의 아침. 마성이 계산을 까먹는 바람에 신호등이 7초인지 70초인지 모르고, 버스는 엉뚱한 정류장에 선다. 마성은 길마다 "숫자 갈림길"을 세우고 맞는 답을 기다린다. 새벽: "마성은 누가 맞는 답을 알려 줘야 다시 기억해. 맞는 문을 지나가면 그 구역 신호가 돌아와."
- **운전 연습 (3단계):** 속도 올리기 → 차로 바꾸기 → 첫 깃발 문 지나기 (1×1 같은 쉬운 문제).
- **장마다:** 짧은 출발 무전 → 문제 10개 주행 (중간에 새벽의 힌트 무전 1번) → 장면 1장 ("도심 신호등이 다시 켜졌다!") → 별 1~3개.
- **엔딩:** 마성 타워에서 모든 단을 섞어 푼다. 마성이 다시 켜지며 말한다. "고마워요. 이제 7 곱하기 8은 56이라는 걸 잊지 않을게요." 오 사장이 이름표를 달아 준다.

### 8.3 장 구성 (구구단 1부)

교과서에서 배우는 순서(2·5단 → 3·6단 → 4·8단 → 7단 → 9단 → 1단과 0의 곱)를 따르고, 원본 배경 8곳에 한 단씩 맞춘다.

| 장 | 배경 | 단 | 고쳐지는 것 |
| --- | --- | --- | --- |
| 1 | 도심 | 2단 | 신호등 |
| 2 | 시골길 | 5단 | 버스 시간표 |
| 3 | 개울 | 3단 | 다리 차단기 |
| 4 | 산악 | 6단 | 케이블카 |
| 5 | 고속도로 | 4단 | 톨게이트 |
| 6 | 오프로드 | 8단 | 택배 창고 |
| 7 | 눈길 | 7단 | 제설차 |
| 8 | 해안 | 9단 | 등대 |
| 9 | 마성 타워 (도심, 밤) | 1단·0의 곱 + 모든 단 섞기 | 마성의 계산 칩 |

- 각 장 안에서도 6.1의 단계를 따른다: 처음 판은 순서대로, 다음 판은 섞어서.
- **장 깨기 기준:** 10문제 중 7개 이상 맞히면 다음 장이 열린다. 별은 7~8개 1개, 9개 2개, 10개 3개. 못 깨도 새벽이 격려하고 틀린 문제를 먼저 내서 다시 해 본다.
- 교사는 설정에서 모든 장을 열 수 있다 (원본의 「모두 열기」를 그대로 씀).

### 8.4 맞춤법 2부 (예정)

마성의 계산 칩을 고치자, 이번에는 **글자 칩**이 말썽이다. 도로 표지판과 안내 방송의 글자가 틀린다 ("천천이 가세요", "어린이 보호 구역 안 돼요"). 같은 배경을 다시 돌며 맞춤법 묶음 하나씩(되/돼, 안/않 …)을 고친다.

### 8.5 쓰는 원본 부분

- 이야기 화면(`#story`), 무전 자막(`radio()`), 운전 연습 틀(`TUT`), 엔딩 화면은 그대로 쓰고 글만 바꾼다 (`src/js_story.js`, `src/js_gb.js`).
- 원본의 시작 예고편(`OPENING`)은 프롤로그 장면 3장으로 바꾼다.
- 이야기 글은 초등 2학년이 읽을 수 있게 한 장면 2~3문장, 어려운 한자어 없이 쓴다.

## 11. 기술 방향

- 원본과 같은 방식: `src/` 조각 + `build.sh` → `index.html` 한 파일, Three.js r128, GitHub Pages.
- 새 조각 파일: `js_quiz.js`(출제기·오답 생성·반복 학습), `js_gate.js`(깃발 문·판정), `js_learn_ui.js`(고르기·결과·기록 화면), `js_chapters.js`(장 구성·무전·장면 글), `data/*.json`(문제 묶음, 빌드 때 합침).
- 출제기는 3D와 분리된 순수 함수로 만들어 Node로 단위 시험한다 (오답 규칙, 정답 위치 반반, 중복 없음).
- 저장: `localStorage` 새 키 `pokju-edu-v1`. 이름·학번 같은 개인정보는 저장하지 않는다.
- **결정: 서버 없음.** 기록은 각 기기에만 저장하고, 교사는 결과 화면을 눈으로 확인한다. 반 기록 모으기는 필요해지면 따로 설계한다.

## 12. 성공 기준

- 학생 한 판(문제 10개)이 3분 안에 끝난다.
- 같은 학생이 5판 뒤 구구단 정답률과 평균 답한 시간이 좋아진다 (기록 탭에서 확인 가능).
- 보급형 태블릿에서 화질 「낮음」으로 30fps 이상.
- 출제기 단위 시험 통과: 81개 곱셈 모두 보기 중복 없음, 정답 위치 왼쪽·오른쪽 비율 45~55%.
